skin_segment: - objasnjena i u komentarima u kodu
- Converts to a color space where skin tones are easier to isolate: yCrCb (Y: brightness (luminance), Cr/ Cb: chrominance (color components).)
- Applies thresholds to Cr, Cb, and Y values to detect skin. (All three conditions must be satisfied simultaneously to label a pixel as "skin".)
- Builds a mask highlighting probable skin regions.
- Applies the mask to the original image to segment out skin.

mean_bgr = np.true_divide(batch.sum(axis=(1, 2)), (batch != 0).sum(axis=(1, 2)) + 1e-6)
  - batch.sum(axis=(1, 2)) --> tells NumPy to sum over the height and width dimensions (128 × 128 pixels).
  - This leaves: 6300 images, For each image, it returns one sum per channel (B, G, R). --> output shape: (6300, 3)
  - batch != 0 --> Produces a boolean array of the same shape (6300, 128, 128, 3) (True where pixel value is !=0)
  - .sum(axis=(1, 2)) --> You get, for each image, the count of non-zero pixels per channel. --> Result shape: (6300, 3)
  - + 1e-6 --> Adds a tiny value (epsilon) to prevent division by zero if any channel has only zero pixels
  - np.true_divide() --> obicni division element-wise
  - ostatak koda: mijenja redosljed boja iz BGR u RGB

get_rppg(mean_rgb, person, task, encode_format): (objasnjeno -> pogledaj funkciju get_pulse iz POS.py)
 GOAL: To extract a remote photoplethysmography (rPPG) signal from the average RGB values over time (mean_rgb) extracted from skin pixels.
 - This function is computing an estimated pulse signal from that data using the POS (Plane-Orthogonal-to-Skin) algorithm, 
  a common method in remote photoplethysmography (rPPG) to extract heart rate from color changes in facial skin over time.
  - Extract a 1D signal H representing pulse (heart rate) from a sequence of RGB color values measured over time.

- The reason the training is split into HR-only first, then HR + classification later is to improve learning stability and performance. Here's why:
  1. Heart rate (HR) estimation is often easier and more direct than stress classification because:
      HR is a continuous and objective signal.
      Stress classification is higher-level and more abstract, often requiring understanding patterns in HR and other features.
  2. Step-by-step learning = better feature extraction. By starting with HR:
      The feature extractor (e.g., BVPFeatrueExtraction) learns to focus on relevant physiological signals.
      Then, the classifier (in the "both" phase) can build on those already-learned features for stress prediction.
      This is similar to transfer learning or curriculum learning — teach the network simpler tasks first, then harder ones.
  3. Reduces overfitting and confusion early on. If the model tried to learn both tasks at once from the beginning, it might:
      Struggle to balance the two losses.
      Learn less optimal features for either task.
